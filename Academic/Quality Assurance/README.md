# Quality Assurance Coursework

This coursework follows a Student Grading System and a Hangman application through planning, testing, reporting, and defect management. It also includes research on software quality processes and test automation frameworks.

## File Guide

### `K.McMahon_Module01CourseProject_1102026.docx`

[Open the Configuration Management Plan](K.McMahon_Module01CourseProject_1102026.docx)

A configuration management plan for a Student Grading System. It defines team responsibilities, controlled project items, repository use, baselines, version numbers, release packages, change approval, and reporting. This file demonstrates how project documents and software changes can be kept organized and traceable.

### `K.McMahon_Module02Asssignment_1182026.docx`

[Open the Hangman Software Test Plan](K.McMahon_Module02Asssignment_1182026.docx)

A software test plan for a Hangman application with five functional and five non-functional test cases. It covers game resets, correct and incorrect guesses, win and loss behavior, invalid input, blank input, multiple-character input, response time, and stability. This file demonstrates test case design for both user behavior and system quality.

### `K.McMahon_Module02CourseProject_1182026.docx`

[Open the Student Grading System Requirements](K.McMahon_Module02CourseProject_1182026.docx)

A software requirements specification for a Student Grading System. It defines expected behavior for classes, students, assessments, grade entry, cumulative scores, and averages, along with usability, reliability, performance, and support needs. This file demonstrates how business needs are converted into clear and testable requirements.

### `K.McMahon_Module03Assignment_1252026.pptx`

[Open the Software Quality Assurance Processes presentation](K.McMahon_Module03Assignment_1252026.pptx)

A presentation explaining how organizations define, train, apply, and audit software quality processes. It reviews CMMI, ISO 9000, and Six Sigma, including the benefits and limitations of each approach. This file demonstrates the ability to explain formal quality practices to a business audience.

### `K.McMahon_Module03Asssignment_1242026.docx`

An alternate submitted copy of the Student Grading System software test plan. It covers the same core test areas as the course project version, including courses, students, assessments, grade entry, calculations, dropdown behavior, and navigation. It is retained to preserve the original academic submission set.

### `K.McMahon_Module03CourseProject_1242026.docx`

[Open the complete Student Grading System Test Plan](K.McMahon_Module03CourseProject_1242026.docx)

A complete manual test plan for the Student Grading System. It turns the system requirements into functional and non-functional test cases for course setup, student records, assessments, grades, average calculations, dropdown lists, and interface navigation. This file demonstrates requirements-based test design and a practical black-box testing approach.

### `K.McMahon_Module04Asssignment_292026.docx`

[Open the Hangman Software Test Report](K.McMahon_Module04Asssignment_292026.docx)

An execution report for the earlier Hangman test plan. It records the result of each functional and non-functional test and identifies a failure in the behavior that occurs when the player reaches zero remaining guesses. This file demonstrates accurate expected-versus-actual reporting and the connection between test execution and defect discovery.

### `K.McMahon_Module04CourseProject_292026.docx`

[Open the Student Grading System Test Execution Report](K.McMahon_Module04CourseProject_292026.docx)

A manual black-box test execution report for the Student Grading System. It records results for courses, students, assessments, grade entry, calculations, interface behavior, performance, and stability. This file demonstrates structured execution, result tracking, and clear reporting against a formal test plan.

### `K.McMahon_Module05Assignment_282026.pptx`

[Open the Test Automation Framework Recommendations](K.McMahon_Module05Assignment_282026.pptx)

A comparison of Playwright, Cypress, and Selenium WebDriver. The presentation considers browser support, ease of use, maintenance, reliability, and project needs before recommending an approach. This file demonstrates tool research and framework selection based on practical testing requirements.

### `K.McMahon_Module06Asssignment_292026.docx`

[Open the Hangman Defect Reports](K.McMahon_Module06Asssignment_292026.docx)

A set of defect reports created from the Hangman execution results. Each report records the failed test, severity, expected behavior, actual behavior, and repeatable steps. This file demonstrates how test failures are turned into clear, developer-ready defect records.

### `K.McMahon_Module06CourseProject_2102026.docx`

[Open the Student Grading System Defect Reports](K.McMahon_Module06CourseProject_2102026.docx)

A set of defect reports for the Student Grading System, including an issue where a newly added course does not appear in the main course dropdown. The reports connect observed behavior to test evidence and include severity, expected results, actual results, and reproduction steps. This file demonstrates defect traceability and clear communication between testing and development.
